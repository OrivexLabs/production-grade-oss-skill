# Security Policy

## Supported versions

Security fixes are considered for the latest published version and the default branch. Older revisions may not receive fixes.

## Reporting a vulnerability

Please report suspected vulnerabilities privately through the repository owner's GitHub security-advisory or private vulnerability-reporting channel. Do not put credentials, exploit code, personal data, or an actionable vulnerability in a public issue or pull request.

Include the affected version or commit, impact, reproduction steps that do not expose real secrets, and any suggested mitigation. If sensitive artifacts are needed, redact them and use the private channel.

## Response

Reports are triaged privately. The maintainers will acknowledge receipt when practicable, assess impact and affected versions, coordinate a fix, and publish a clear advisory or changelog entry when disclosure is safe. This policy does not promise a particular response time.
